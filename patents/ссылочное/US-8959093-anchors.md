# US-8959093-B1 — Ranking search results based on anchors

- **Владелец:** Google (выдан Google Inc., сейчас Google LLC)
- **Подана / Выдана:** 15.03.2010 / 17.02.2015
- **Приоритет:** 15.03.2010 · **Истекает:** 02.11.2030
- **Изобретатель:** Ajay P. Nerurkar
- **Тема:** ссылочное / анкорный текст / поведенческие факторы
- **Ссылка:** https://patents.google.com/patent/US8959093B1/en

> Патент имеет код **B1**, а не B2: у него не было предварительной публикации заявки.

## Суть в двух словах

Патент описывает, как **перенести поведенческий сигнал с документа-посредника на первоисточник по ссылке между ними**.

Ситуация, которую он решает. По запросу в выдаче стоят две страницы: агрегатор (например, статья в Википедии или новостной обзор) и первоисточник, на который агрегатор ссылается. Пользователи кликают на агрегатор, потому что он выше, а внутри переходят по ссылке на первоисточник — то есть на самом деле им был нужен первоисточник. Но вся заслуга по клику достаётся агрегатору, и он продолжает расти в выдаче, а первоисточник — нет.

Решение: если обе страницы есть в выдаче по одному запросу **и** первая ссылается на вторую, то клики по первой засчитываются в пользу второй. Анкорный текст ссылки при этом работает пропускным условием — перенос происходит, только если анкор релевантен запросу.

## Формула, по пунктам

Всего 20 пунктов. Независимых три — 1, 11 и 16: это одно и то же изобретение в трёх юридических формах (способ, носитель с программой, система). Разбираем пункт 1, остальные два ему дословно параллельны.

**Пункт 1 (независимый) — четыре шага:**

1. Получить по запросу набор результатов, среди которых есть **первый документ** и **второй документ**.
2. Определить, что первый документ **содержит ссылку** на второй — и тоже присутствующий в этой же выдаче.
3. Раз ссылка есть — вычислить для второго документа *quality of result statistic* на основе двух величин:
   - меры прошлых кликов **по первому документу** по этому запросу,
   - меры прошлых кликов **по второму документу** по этому запросу.
4. Передать полученную величину на вход алгоритму ранжирования этой выдачи.

То есть ядро защиты — сам факт, что клики по странице-донору участвуют в расчёте качества страницы-акцептора, когда обе стоят в одной выдаче и первая ссылается на вторую.

**Зависимые пункты — тут вся практическая механика:**

| № | Что добавляет |
|---|---|
| 2 | Часть кликов по первому документу **прямо записывается** как поведенческие данные второго |
| 3 | Учитываются также клики по второму документу **по другому запросу** |
| 4 | Перенос работает, **только если домены разные** — внутренние ссылки не считаются |
| 5 | Перенос работает, **только если анкорный текст релевантен запросу** |
| 6 | Релевантность анкора = его часть **совпадает с частью запроса** |
| 7 | Дополнительно учитываются клики **по самой ссылке** внутри первого документа |
| 8 | Меры кликов по обоим документам **агрегируются** |
| 9 | У первого документа его мера кликов **уменьшается** — сигнал именно переносится, а не копируется |
| 10 | Вклад масштабируется **степенью** релевантности анкора запросу |
| 11–15 | То же, оформленное как компьютерный программный продукт |
| 16–20 | То же, оформленное как система |

## Что это значит для SEO

**1. Анкор — это условие допуска, а не просто вес.** По пунктам 5, 6 и 10 перенос сигнала включается только при совпадении анкора с запросом, и его величина зависит от степени совпадения. Ссылка с анкором «тут» и ссылка с анкором по теме запроса работают принципиально по-разному: вторая открывает канал передачи, первая — нет.

**2. Ценна ссылка со страницы, которая сама ранжируется и получает клики по вашему запросу.** Механизм требует, чтобы **оба** документа стояли в выдаче по одному запросу. Ссылка с популярной, но нерелевантной запросу страницы этот канал не открывает. Это смещает приоритет с «ссылка с трастового домена» на «ссылка с конкретной страницы, конкурирующей с вами в той же выдаче».

**3. Внутренние ссылки не работают.** Пункт 4 прямо требует разных доменов. Перелинковка внутри сайта этот механизм не запускает.

**4. Быть первоисточником выгодно, быть агрегатором — нет.** Пункт 9 уменьшает меру кликов у ссылающейся страницы. Патент прямо задуман, чтобы сдвигать агрегаторы вниз, а цитируемые ими первоисточники — вверх. Для контентной стратегии это аргумент в пользу оригинальных материалов, на которые ссылаются обзорщики, а не в пользу компиляций.

**5. Клики по самой ссылке учитываются отдельно** (пункт 7). Заметность ссылки в теле страницы — не только факт её наличия — имеет значение.

**Оговорка.** Это патент, а не подтверждение работающего механизма. Google патентует существенно больше, чем внедряет, и патент 2010 года мог не дойти до продакшена или дойти в неузнаваемом виде. Использовать как рамку для понимания логики, а не как описание текущего алгоритма.
