# US-8078629-B2 — Detecting spam documents in a phrase based information retrieval system

- **Владелец:** Google (выдан Google Inc., сейчас Google LLC)
- **Подана / Выдана:** 13.10.2009 / 13.12.2011
- **Приоритет:** 26.07.2004
- **Изобретатель:** Anna Lynn Patterson
- **Тема:** текстовая оптимизация / фразовый индекс / переоптимизация
- **Ссылка:** https://patents.google.com/patent/US8078629B2/en

> ⚠️ **Это не ссылочный патент.** Формула работает с **фразами внутри документа**, ссылки в ней не упоминаются. Карточка отнесена к `patents/text-optimization/`.
>
> Автор — **Anna Lynn Patterson**, создательница фразового индекса Google. Продолжение `US-7603345-B2` (2009).

## Суть в двух словах

Патент описывает, как **ловить переоптимизацию, сравнивая количество связанных фраз в документе с тем, сколько их там должно быть по статистике корпуса**.

Ситуация, которую он решает. Естественный текст про ипотеку неизбежно содержит сопутствующие выражения: ставка, первоначальный взнос, срок кредита. Их количество не случайно — оно колеблется вокруг некоторой нормы. Текст, написанный ради поисковика, эту норму нарушает: связанных фраз в нём либо неестественно много, либо подозрительно мало при обилии целевой фразы.

Решение: пройти по индексу, посчитать для каждой фразы, **сколько связанных с ней фраз обычно встречается** в документах, и получить **ожидаемое число**. Затем для проверяемого документа посчитать **фактическое** число и сравнить. Расхождение — признак спама.

## Формула, по пунктам

Всего 36 пунктов. Независимых четыре: 1, 16, 19 и 34. Разбираем пункт 1.

**Пункт 1 (независимый) — три шага:**

1. Определить для документа, содержащего **первую фразу**, **ожидаемое количество связанных фраз**, которые должны в нём присутствовать. Ожидаемое число выводится так: **пройти по индексу множества документов**; для каждого проиндексированного документа определить набор фраз и **для каждой фразы — сколько связанных с ней фраз также есть в этом документе**; вывести ожидаемое число **по всем пройденным документам**.
2. Определить для этого документа и этой фразы **фактическое количество** присутствующих связанных фраз.
3. **Признать документ спамом**, сравнив фактическое количество с ожидаемым.

**Зависимые пункты:**

| № | Что добавляет |
|---|---|
| 2 | Ожидаемое число берётся как **медиана** по пройденным документам, а не как среднее |
| 3 | Проверка повторяется для **второй фразы** документа — оценка не по одной фразе |
| 4–15 | Уточнения подсчёта и порогов |
| 16–18, 19–33, 34–36 | Те же механизмы в других юридических формах |

## Что это значит для SEO

**1. Существует верхняя граница насыщенности текста, и она вычисляется, а не назначается.** Норма выводится из корпуса (шаг 1), то есть из того, как пишут все остальные по этой теме. «Достаточно раскрытая тема» имеет измеримый диапазон, и выход за верхнюю границу так же подозрителен, как недобор.

**2. Медиана вместо среднего** (пункт 2) — техническая, но важная деталь. Медиана устойчива к выбросам: несколько гигантских переоптимизированных документов не сдвинут норму. Подтянуть планку массовым спамом не получится.

**3. Проверяется не плотность ключа, а окружение** (шаг 1). Считаются **связанные фразы**, а не повторы целевой. Текст, где ключ повторён двадцать раз без сопутствующей лексики, провалится именно по недостатку связанных фраз.

**4. Оценка идёт по нескольким фразам** (пункт 3). Выровнять один блок недостаточно — аномалия ищется по разным фразам документа.

**5. Практический вывод прост и неожиданно традиционен.** Лучший способ попасть в норму — писать так, как пишут люди, действительно разбирающиеся в теме: сопутствующая лексика появится сама и в естественной пропорции.

**Оговорка.** Это патент, а не подтверждение работающего механизма. Google патентует существенно больше, чем внедряет, и патент 2004 года мог не дойти до продакшена или дойти в неузнаваемом виде. Использовать как рамку для понимания логики, а не как описание текущего алгоритма.
