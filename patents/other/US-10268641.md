# US-10268641-B1 — Search result ranking based on trust

- **Владелец:** Google (выдан Google Inc., сейчас Google LLC)
- **Подана / Выдана:** 29.07.2014 / 23.04.2019
- **Приоритет:** 09.05.2006 · **Истекает:** 30.10.2026
- **Изобретатель:** Ramanathan V. Guha
- **Тема:** доверие пользователя к источникам / аннотации / персонализация выдачи
- **Ссылка:** https://patents.google.com/patent/US10268641B1/en

> ⚠️ **Вопреки ожиданиям, это не ссылочное ранжирование.** Ни ссылок, ни анкоров, ни графа в формуле нет. Доверие здесь — **явная оценка, которую пользователь ставит сущности через элемент интерфейса**, а ранжирование строится на **аннотациях**, поданных этими сущностями. Патент попал в ядро каталога по названию «ranking based on trust», а не по механизму. Карточка вынесена в `patents/other/`.
>
> Четвёртая публикация семьи: `US-7603350-B1` (2009) → `US-8352467-B1` (2013) → `US-8818995-B1` (2014) → эта.

## Суть в двух словах

Патент описывает, как **дать пользователю вручную назначать степень доверия к источникам по конкретным темам и ранжировать выдачу по этим оценкам**.

Ситуация, которую он решает. Поисковик решает за пользователя, каким источникам верить. Но доверие тематично и субъективно: врач доверяет одним ресурсам по медицине и другим по ремонту автомобиля, и его набор не совпадает с набором соседа.

Решение: показать пользователю интерфейс с кнопкой доверия и списком тем; пользователь нажимает и выбирает темы, по которым доверяет этой сущности. Система записывает **оценку пользователя для этой сущности по этим темам**. Дальше выдача по его запросам ранжируется с учётом того, насколько он доверяет источникам, **приславшим аннотации** к документам.

## Формула, по пунктам

Всего 20 пунктов. Независимых три — 1, 13 и 17. Разбираем пункт 1.

**Пункт 1 (независимый) — четыре шага:**

1. Показать на устройстве пользователя **интерфейс, связанный с конкретной сущностью**, содержащий (i) **интерактивный элемент управления**, который по нажатию заставляет другое устройство назначить оценку, и (ii) **интерфейс выбора тем** для этой сущности.
2. Получить данные о том, что пользователь (i) **взаимодействовал с элементом** и (ii) **выбрал одну или несколько тем** из предложенных.
3. Передать эти данные по сети, чтобы второе устройство **назначило оценку пользователя относительно данной сущности по выбранным темам**. Оценка указывает поисковой системе, **в какой степени полагаться** на контент этой сущности по этим темам при ответах на запросы именно этого пользователя.
4. В ответ на запрос пользователя получить результаты, **ранжированные с учётом этой оценки**, причём результаты ссылаются на документы, **к которым сущности подали аннотации**, и ранжирование строится **на тексте аннотаций и оценках доверия** к их авторам.

**Зависимые пункты:**

| № | Что добавляет |
|---|---|
| 2 | Передаются данные, **идентифицирующие пользователя** |
| 3 | Элемент управления — **кнопка на веб-странице**, оценки записываются |
| 4 | Показывается **список сущностей**, с которыми у пользователя есть заданные отношения |
| 5 | Список показывает **имена сущностей или их страницы** |
| 6 | Система использует **несколько аннотаций** при отборе результатов |
| 7 | Оценки по разным темам **комбинируются взвешивающей функцией** |
| 8 | Пользователь может **задать числовое значение** оценки, а не только факт доверия |
| 9 | Оценка **сохраняется** после получения данных о взаимодействии |
| 10 | Устанавливаются **новые отношения** между пользователями |
| 11 | Результаты берутся из документов с **совпадающими аннотациями** |
| 12 | Уровень доверия **меняется** по мере выбора тем |
| 13–16, 17–20 | То же как носитель и как система |

## Что это значит для SEO

**1. Тематическое доверие здесь не вычисляется, а декларируется.** В отличие от ссылочных механизмов, где авторитет выводится из графа, тут источник доверия — прямое действие пользователя. Никакой оптимизацией это не «зарабатывается»: нужно, чтобы конкретные люди нажали кнопку.

**2. Аннотации — самостоятельный ранжирующий вход** (пункты 4, 6, 11). Документы отбираются и упорядочиваются **по тексту аннотаций**, поданных доверенными сущностями. Это модель, где поверх документа лежит слой чужих комментариев, и именно он ранжируется.

**3. Доверие тематично, а не глобально** (пункты 1 и 12). Оценка привязана к паре «сущность + тема». Источник, которому доверяют по одной теме, не получает преимущества по другой. Для контентной стратегии это довод за узкую специализацию, а не за широкий охват.

**4. Персонализация здесь полная, а не поправочная** (пункт 3). Оценка действует «относительно запросов от этого пользователя». Выдача двух людей может отличаться радикально, и понятия единой позиции в такой модели не существует.

**5. Практическая применимость сомнительна.** Механизм требует массового ручного действия от пользователей. Продукта Google, работающего так, не известно, а сама идея близка к закрытым Knol и Google+ по духу времени (приоритет 2006 года).

**Оговорка.** Это патент, а не подтверждение работающего механизма. Google патентует существенно больше, чем внедряет, и патент 2006 года мог не дойти до продакшена или дойти в неузнаваемом виде. Использовать как рамку для понимания логики, а не как описание текущего алгоритма.
