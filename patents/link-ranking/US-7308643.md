# US-7308643-B1 — Anchor tag indexing in a web crawler system

- **Владелец:** Google (выдан Google Inc., сейчас Google LLC)
- **Подана / Выдана:** 03.07.2003 / 11.12.2007
- **Приоритет:** 03.07.2003 · **Истекает:** 09.02.2025 (истёк)
- **Изобретатели:** Huican Zhu, Jeffrey Dean, Sanjay Ghemawat, Bwolen Po-Jen Yang, Anurag Acharya
- **Тема:** ссылочное / анкорный текст / инфраструктура индексации
- **Ссылка:** https://patents.google.com/patent/US7308643B1/en

> Первая публикация самой длинной семьи каталога: эта → `US-8484548-B1` (2013) → `US-9305091-B2` (2016) → `US-2016321252-A1` → `US-10210256-B2` (2019). Шестнадцать лет продолжений. Авторы — костяк инфраструктурной команды Google.

## Суть в двух словах

Патент описывает, как **перевернуть ссылочный лог: из списка «кто куда ссылается» получить список «на кого кто ссылается»**.

Ситуация, которую он решает. Краулер обходит веб постранично и естественным образом накапливает данные в форме «документ-источник → список его исходящих ссылок». Но для ранжирования нужно обратное: по целевому документу мгновенно получить всех, кто на него ссылается, и их анкоры. Перебирать ради этого весь лог невозможно.

Решение: строить из ссылочного лога **отсортированную анкорную карту** (*sorted anchor map*), где записи идут по идентификатору **целевого** документа и каждая содержит список входящих ссылок с аннотациями. Это и есть та структура, из которой анкорные сигналы попадают в ранжирование.

## Формула, по пунктам

Всего 27 пунктов. Независимых два — 1 и 19. Разбираем пункт 1.

**Пункт 1 (независимый) — два шага:**

1. Обратиться к **ссылочному логу** (*link log*) из множества записей. Каждая запись идентифицирует **документ-источник** и **список целевых документов**, на которые ведут его исходящие ссылки; запись содержит идентификатор источника и идентификаторы целей. Записи строятся по информации, **извлечённой из обойдённых краулером документов**.
2. Выдать **отсортированную анкорную карту**, соответствующую этому логу, из множества анкорных записей. Каждая анкорная запись идентифицирует **целевой документ** и **список входящих ссылок** — то есть источники, содержащие ссылки на эту цель. Записи **упорядочены по идентификаторам целевых документов**.

То есть ядро защиты — сама операция инверсии ссылочного лога в упорядоченную по целям структуру.

**Зависимые пункты:**

| № | Что добавляет |
|---|---|
| 2 | Каждая анкорная запись содержит **список аннотаций** |
| 3 | Каждая аннотация соответствует **конкретной входящей ссылке** от конкретного источника |
| 4 и далее | Уточнения состава аннотаций: что именно сохраняется о каждой входящей ссылке |
| 19–27 | То же, оформленное во второй юридической форме |

## Что это значит для SEO

**1. Анкорные данные существуют отдельно от документа и живут своей жизнью.** Анкорная карта строится из лога краула, а не из целевой страницы. Изменение собственной страницы не меняет того, что о ней записано в этой структуре, — обновление приходит только с новым обходом ссылающихся документов.

**2. Задержка в учёте ссылки определяется обходом донора, а не вашим сайтом.** Запись в лог появляется, когда краулер обошёл страницу-источник. Отсюда практический вывод, совпадающий с пунктом 3 патента [[US-8407231]]: ссылка начинает работать не с момента размещения, а с момента обхода донора.

**3. Аннотации хранятся по каждой входящей ссылке отдельно** (пункты 2 и 3). Не агрегированно, а поимённо: для каждой ссылки — своя запись. Значит, разнообразие анкоров сохраняется в структуре целиком и доступно любым последующим алгоритмам.

**4. Масштаб структуры объясняет, почему ссылочное считается пакетно.** Карта сортируется по идентификаторам целей и пересобирается при обновлении. Это архитектурная причина, по которой ссылочные эффекты проявляются не мгновенно, а волнами.

**5. Семья живёт с 2003 по 2019 год.** Пять публикаций за шестнадцать лет — признак того, что Google считал механизм достаточно важным, чтобы непрерывно продлевать защиту.

**Оговорка.** Это патент, а не подтверждение работающего механизма. Google патентует существенно больше, чем внедряет, и патент 2003 года мог не дойти до продакшена или дойти в неузнаваемом виде. Срок действия истёк в феврале 2025 года. Использовать как рамку для понимания логики, а не как описание текущего алгоритма.
